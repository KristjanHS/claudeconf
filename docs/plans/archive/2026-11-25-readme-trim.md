## Diagnosis

The README is a hub that also tries to be the catalog, the design doc, the evidence log and the
adoption guide. Most of its length repeats `docs/system.md`, `docs/why.md`, `ADOPT.md` and
`.claude/hooks/README.md`.

Detection pass (`detect-ai-text-cl-op`): the sentence statistics look human-ish (burstiness 0.96).
That is mostly because tables and lists break up the prose. The structural tells are strong:
template parallelism, layered signposting, repeated caveats and heavy bolding. Verdict: **mixed /
AI-drafted and human-edited**. Pattern-matching only, not proof.

Second pass (`brutal-honesty-review`, §7) found problems that go beyond style. The page claims evidence
it doesn't have. It has no single identity. Its tests lock in the bloated layout. Read §7 first: it
changes the skeleton in §5.

## 2. Emoji

- 31 emoji: one on every `##` heading plus a duplicate in the TOC. They add colour, not meaning.
  Remove them all. If you want visual structure, the badges and the statusline GIF are enough.
- **Coupling, so do this in one commit:** GitHub slugs the emoji into the anchor (`## 🤝 Adoption` →
  `#-adoption`). Removing the emoji changes every anchor to `#adoption` and so on, which breaks:
  - `docs/system.md` (lines 3, 21, 25, 26, 48, 49, 85, 88) and `docs/why.md` (lines 5, 14, 30, 31, 42, 48)
  - `tests/test_readme_hub.py`: the hardcoded `#-adoption` set (line 75), the parametrized
    `-does-this-actually-work` / `-adoption` fragments (lines 104–105) and the planted fixture (line 128)
  - Run `make -C ~/projects/claudeconf test` after the rename. `test_hub_targets_resolve` and
    `test_docs_readme_anchors_resolve` will flag any anchor that was missed.
- Deleted sections (Glossary, How it works, Beyond context, skills detail) also drop anchors that
  `docs/` cites. Re-point those cites to `docs/catalog.md` / `docs/system.md`.

## 7. Second pass: brutal-honesty review (Bach/Ramsay mode)

Weighted findings: 2 CRITICAL, 4 HIGH, 3 MEDIUM, 1 LOW (score 19.5).

**F1 — CRITICAL: the page has three identities.** The tagline says "a tested method for agentic
coding". "What this is" says "a copy-in catalog … that keeps a session's context window lean". Then it
says the repo "has grown into the wider set of … practices", and the GIF caption sells a statusline. A
reader can't say what they'd get in 10 seconds.
*Fix:* pick one. The evidence on the page (statusline, budget governor, context-cost table) all points
to **context-budget tooling for long Claude Code sessions**. Lead with that. Describe the skills and
conventions in one line as "plus the rest of my config".

**F2 — CRITICAL: "Does this actually work?" contains no evidence that it works.** It opens with
"the evidence below shows cost reduction for an existing Claude Code user". Then it shows file sizes and
threshold constants. Those are inputs, not outcomes. Neither the README nor `docs/why.md` or
`docs/system.md` has a before/after measurement: no tokens per session, compactions avoided, or cost per
task. Claiming a result next to a table of config values is the clearest credibility leak on the page.
*Fix:* either add one real outcome measurement (e.g. median session tokens or compaction count over N
sessions, with vs without), or rename the section "What's measured" and delete the "shows cost
reduction" sentence. Don't keep the claim without the data.

**F3 — HIGH: "Deferred tokens ~38,684" implies savings against a strawman baseline.** Deferred tokens
are only saved if the alternative was inlining every rule and reference into `CLAUDE.md`, which nobody
does. Rules also load anyway when a matching file is touched.
*Fix:* state the always-loaded cost (`CLAUDE.md` 5,006 bytes ≈ 1.25k tokens per turn) as the headline
number. That is true and impressive enough. Present deferred bytes as "available on demand", not as a saving.

**F4 — HIGH: "Built with this method" advertises absence.** ADRs: 6/6 "—". In prod since: 5/6 "—".
Releases: 4/6 "—". The table lists claudeconf itself and kri-local-rag, which the page says predates the
method. Test and line counts show the repos exist, not that the method helped build them.
*Fix:* drop the ADRs and In-prod columns, and drop Releases unless it gets filled in. Remove
claudeconf and kri-local-rag rows. Or replace the table with three linked repos plus one sentence each
on what the method caught there (`docs/why.md` already has these trails).

**F5 — HIGH: Adoption is a vanity metric with upkeep.** 227 clones / 80 uniques over 14 days is GitHub
traffic, largely bots and CI. A dated, auto-regenerated block that goes stale is a liability on a page
about avoiding bloat. → Drop it (§1).

**F6 — HIGH: the tests lock in the bloated layout.** `test_readme_hub.py` asserts the nav label order
including `Adoption`, a **Start here** group containing `#-adoption`, and emoji-derived anchors
(`-does-this-actually-work`). Any trim fails CI, so the layout gets preserved by tests rather than by
judgment.
*Fix:* keep only the useful invariant, "every README link and every `README.md#…` cite from `docs/`
resolves". Delete `test_nav_leads_with_hub_labels_in_order`, `test_start_here_groups_system_why_adoption`
and the hardcoded-fragment parametrization of `test_docs_link_back_to_hub`.

**F7 — MEDIUM: costs are vague while benefits look precise.** Benefits come with byte counts; costs say
"latency on the hot path", "hand-work", "interrupts". Precise-looking benefits next to fuzzy costs read
as salesmanship.
*Fix:* put a number on each cost: hook runtime per call (time `pre-compact.py` /
`docs-bloat-gate.py` once), the always-on `CLAUDE.md` tokens, and the number of `settings.json` lines to
hand-merge.

**F8 — MEDIUM: insider jargon with no definitions.** The page uses `impag`, `qimpag`, "L3 references"
(L1/L2 are never introduced), "S1 size ratchet", "N=3 override sentinels", "sidecar", "keep-10 pool",
"re-nags", "leanness loop", "exemplar", "load-bearing". This is the author's internal config vocabulary
leaking into a public landing page.
*Fix:* on the README, name things by what they do ("plan executor", "on-demand references"). Keep the
internal names in `docs/catalog.md`. Delete "L3" from the README entirely.

**F9 — MEDIUM: the Quick start is clone-then-read-917-words.** `git clone` + "see ADOPT.md" isn't
quick and doesn't start anything. The GIF has already sold the statusline, and `docs/statusline_adopt.md`
exists.
*Fix:* make the Quick start the statusline install (copy script, add one `settings.json` entry, needs
`jq`). Then link ADOPT.md for everything else.

**F10 — LOW: contributor notes on a landing page.** Rows like `lib/ask_paths.py` ("absent → that one
check goes inert") and the per-repo regex footnotes are maintenance detail. → They go to
`docs/catalog.md` with the rest of the catalog.

## 8. Unnecessary complexity

The README is not just long. It is a small software system. Roughly **1,880 lines of code maintain a
503-line page.**

| Machinery | Size | Verdict |
|---|---|---|
| `scripts/adoption_signals.py` + `tests/test_adoption_signals.py` + `make adoption-block` | 201 + 238 lines | **Delete** (F5). Needs `gh` auth and network, and the block goes stale by date |
| `scripts/agentic_stats.py` + `tests/test_agentic_stats.py` | 440 + 424 lines | Over-built for a 6-row table that changes rarely: per-language regex test counting, `scc`, per-repo delta-vs-upstream, footnote rendering. **Replace with a hand-written 3-row list** (F4), or keep the script for your own portfolio and stop rendering it into the README |
| `scripts/context_cost.py` + `tests/test_context_cost.py` + `make test` step [5/5] | 225 + 214 lines | The one block worth keeping, but trim it to ~5 rows. The staleness check in `make test` means every rule edit forces a README regen commit. Consider moving the check to CI only, or dropping the date footer so a regen without value changes produces no diff |
| `tests/test_readme_hub.py` | 140 lines | Tests that the *layout* is right (nav label order, Start-here group membership, emoji anchors). **Cut to the link-resolution check** (F6). `tests/test_doc_links.py` (repo-wide) already covers most of it |

On the page itself:

- **A link graph inside one page.** There are 33 internal `#-…` links, including 5 back-references to "the
  measured table". The nav line, a 4-group TOC, "How it works" (a section that only links to other
  sections) and per-section cross-links form 4 navigation layers for one scrolling page. **Target: 0–3
  internal links.** A ~100-line page doesn't need navigation.
- **Self-referential indirection.** Sections point at table rows ("count: the *Hooks* row") instead of
  saying the number. The README is written as if its parts could drift apart, which the generator setup
  causes. Write the few numbers that matter inline and let the one table hold the rest.
- **73 table rows across 9 tables**, plus a "Source" column citing grep expressions
  (`lines matching (rules\|references)/[\w.-]+\.md`). Audit trail belongs in the script, not on the
  landing page. → Drop the Source column, or show it only in `docs/catalog.md`.
- **Three visuals of one statusline** (GIF + `statusline.png` + `statusline2.png`). → Keep the GIF.
- **HTML scaffolding** (`<div align="center">`, `<p align="left">`, `<sub>`, `<img width>`: 12 lines)
  for centering. → Plain Markdown; drop the centered div.
- **Per-repo methodology footnotes** that vary by language and by "delta vs wire-pod". → Gone with the
  portfolio table.

Simplicity test for the rewrite: a reader should be able to edit the README in any editor, without
running a script, and `make test` should only fail on a broken link.

Keep (from §7): the instinct behind "What it costs you" / "When this isn't worth it" is the best thing
on the page. Few config repos admit costs. Keep it, merged and quantified (F7), without the "skeptic"
framing (§3).
